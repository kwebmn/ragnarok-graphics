# The app's first screen as a game launcher — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
> The owner chose inline execution, a beta per stage, no stops between stages.

**Goal:** uaro-graphics.exe opens on a game launcher (art, «ГРАТИ», «Що нового», four icons, the look line) with a
look picker, a «Журнал змін» screen and picture cards on the first run; the settings app stays behind the gear.

**Architecture:** Pure layout, state and changelog logic in `src/core` (host-tested). One custom-painted Win32 child
view in `src/app/launcher_view.*` composes the screen in software (core/window_panel's Picture, roundRect; JPEG by
stb) and draws words by GDI in IBM Plex Sans (the game's new interface's font, already shipped); MainWindow shows it
first and swaps to today's settings view.

**Tech Stack:** C++17, Win32 + GDI, stb_image, the repo's test harness (`build-host/uagfx_tests`), MinGW cross builds.

**Spec:** `docs/superpowers/specs/2026-11-12-launcher-design.md`

## Global Constraints

- Owner-approved: live art (crossfade 2 s every 20 s, still while the game runs or the window is in the background);
  betas in the changelog for the beta channel only; a look pick applies at once with «Змінено · Скасувати» for 5 s;
  the dark Windows frame (DWM), not a frame of our own; news cards without pictures.
- Every new word in `src/core/settings/strings.cpp` in en, uk, ru (`Text::` enum order kept); UI names quoted from
  the uk column.
- No new DLL imports in uaro-graphics.exe: `DwmSetWindowAttribute` through `LoadLibraryW(L"dwmapi.dll")`.
- No change to ddraw.dll, the game, the site.
- New files' lines at most 120 characters; diff lines at most 121 (the gate).
- Words of the launcher: IBM Plex Sans (`third_party/plex`, OFL), Segoe UI when it fails to load; icons from
  Segoe MDL2 Assets (E713 gear, E8BD chat, E774 globe, E716 people), letters when that font is missing.
- Palette (uaUI style A): card 0x10141C, gold 0xC9A55B, text 0xEEF2F8, muted 0x9AA3B5, ok 0x4CC38A, bad 0xE0564F.

## Review Focus

1. Windows' scaling 175 % on a 4K screen and a small window (960x560 at 96 DPI): no zone outside the client or over
   another — `launcher_layout_fits_small_and_scaled_windows` (Task 3).
2. The site unreachable: no server count, no news — the pill «Сервер недоступний», the feed only the update card —
   `launcher_layout_without_news` (Task 3) and the view's draw with an empty `launcher::Info`.
3. The game running with an update offered: the button offers another window, never an update over a running game —
   `launcher_play_state_running_wins` (Task 3).
4. A package without the art (old install, files deleted): a plain dark ground, no crash —
   `launcher_art_missing_file_is_empty` (Task 4).
5. A notes file with a version heading and no points, or points before the first heading —
   `changelog_parse_odd_files` (Task 2).

**Files:**

**Interfaces (namespace `uagfx::launcherview`):**
- `enum class Part : uint8_t { None, Play, PlayMore, Look, Changelog, News, Settings, Reports, Site, Forum, Version,

- `struct Layout { float s = 1; int w = 0, h = 0; Box bar, logo, server, language, feed, update, news[3], dock[4],

  1280x720: bar 64 high; feed 22 from the left, 80 from the top, 380 wide; dock icons 64 wide, 22 from the left and
  the bottom; play column 336 wide, 26 from the right and the bottom: look 52, button 64, version 18 under it; news
  cards as many as fit above the dock (at most 3); plate 44 high over the dock when asked.
- `struct Hit { Part part = Part::None; int index = -1; };` `Hit hitAt(const Layout& L, float x, float y);`
- `enum class PlayState : uint8_t { Update, Updating, Play, Running };`
  `struct PlayInputs { bool offered = false, downloading = false, gameRunning = false; };`
  `PlayState playState(const PlayInputs& in);` — Running first, then Updating, then Update, else Play.
