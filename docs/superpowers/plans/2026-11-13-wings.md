# Wings on Characters Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** big wings on every player who wears one of nine GM-only headgears, drawn by the driver from the official
garment sets of the uaRO HD client (and their palette recolours), seen by everyone with uaRO Graphics.

**Architecture:** pure rules in `src/core/wings.*` (looks by view, recolours, garment file names, wing quads, the
per-frame bookkeeping that says where a character's wings go) and `src/core/wings_pack.*` (the packed sets); a thin
`src/win/wings.*` reads the player at the game's shadow call (hook in win/effect_hook), asks the game for the
character's screen point and depth scale, notes its faces from the face sort hook, and in `Device7::record` draws the
wings with the driver's own textures right before the character's first face or right after its last.

**Tech Stack:** C++17 (ddraw.dll 32-bit, host tests), Python 3 + PIL-free tooling (tools/wings_pack.py), the GRF
0x200 format (core grf::Archive).

**Spec:** docs/superpowers/specs/2026-11-13-wings-design.md (the owner's concept:
https://claude.ai/artifact/S1rYPnLYM9yByk6wz5FTok).

## Global Constraints

- Client only: no uAthena, server, item or NPC changes; DATA.INI untouched.
- Views -> looks exactly: 365 angel, 382 fallen, 129 demon, 613 fire, 595 ice, 568 valkyrie, 477 gold, 438 sakura,
  562 crimson; any other view: none.
- Sets: angel and fallen = the HD client's `data\sprite\로브\천사날개\` and `로브\타락천사의날개\` (per sex and body name);
  demon = `data\sprite\robe\darkwing` (one for every body). fire, ice, valkyrie, gold, sakura recolour angel; crimson
  recolours demon.
- Recolour stops (t, r, g, b) - fire (0 90 10 0)(0.35 200 50 10)(0.7 255 150 30)(1 255 240 150); ice (0 20 50 120)
  (0.4 60 140 220)(0.75 150 220 250)(1 240 252 255); valkyrie (0 150 105 30)(0.3 225 185 80)(0.55 240 236 225)
  (1 255 255 255); gold (0 120 70 10)(0.45 215 160 40)(0.8 250 225 130)(1 255 250 220); sakura (0 150 60 100)
  (0.45 235 140 180)(0.8 255 205 225)(1 255 240 246); crimson (0 25 0 5)(0.4 110 10 20)(0.75 200 40 40)
  (1 255 140 110).
- No switch: the wings always show (the owner); none in «Пауза» (`Context::enhanced()` false).
- Game memory and game functions only on the game thread (the hooks run there); every read through the driver's
  checked readers (win/game_memory read32 / readGame).
- New lines <= 120 columns (diffs 121), 32/64-bit builds with no warnings, host suite green, ship with gship.sh;
  betas only (3.0.18-beta.N), notes uk/ru/en saying what to check.

## Review Focus

1. A body with no garment file (wedding, Xmas, a transformed character, a job the pack lacks): no wings, one log line
   for that body, nothing else.
2. No `uaro-graphics\wings.grf` (an old install) or a broken one: no wings, one log line, the game as before.
3. A character whose sprites never come after its shadow (hidden, off the screen): no wings drawn for it.
4. Two wearers whose faces interleave in the sorted list: each one's wings with its own faces.
5. Mirrored and scaled garment layers: their quads mirrored and scaled as the game draws such layers.

### Task 2: wing quads, order, the frame's bookkeeping (core)

**Files:** Modify `src/core/wings.hpp/.cpp`; Test `tests/test_wings.cpp`.

**Interfaces:** Produces
`struct Transform { float x = 0, y = 0, scale = 1; };` (the character's screen point; size times depth scale)
`struct Quad { float x0, y0, x1, y1; int image; int type; bool mirror; uint32_t tint; };`
`std::vector<Quad> quads(const spritefile::Act& garment, const spritefile::Act& body, const spritefile::Sprite& s,
size_t action, size_t frame, const Transform& t);` - each layer of the garment frame (frame % its frames) moved by
the body frame's anchor 0 less the garment frame's anchor 0 (either missing: 0): `x0 = t.x + ((L.x + ax) - w *
L.scaleX / 2) * t.scale`, `x1 = x0 + w * L.scaleX * t.scale`, the same for y; layers with no picture skipped; an
action past the garment's: none.
`bool facesAway(size_t action);` - side (action % 8) 3, 4 or 5.
`float lerpAt(float y, float y0, float v0, float y1, float v1);` (a face's depth at another height)
`class Frame` (the bookkeeping): `int begin(uint32_t actor, bool away);` (a job's index), `void face(int job,
uint32_t vertices);`, `struct Emit { int before = -1, after = -1; };` `Emit drawn(uint32_t vertices);`,
`void clear();`.

- [ ] Step 1: tests `wings_quads_by_anchors` (a body frame anchored at (0, -60), a garment frame anchored at (2, -50)
