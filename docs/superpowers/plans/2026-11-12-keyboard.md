# Keyboard Control Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** the game played from the keyboard - arrows walk with an empty chat line, a walk mode (WASD, letters as
actions, Enter for the chat), quick actions, then windows, screens, a key page and the launcher - a beta per stage.

**Architecture:** the keyboard is a second pad: a hook in the game window (win/key_walk, win/walk_mode) turns keys
into a walk vector and actions that the pad runtime merges into the pad controller's input (`PadState::keyWalk`,
key actions), so walking without the mouse (core stick_walk), targets, attack, pick up, NPC talk and slots are the
pad's own code. Pure rules (vectors, gates, the walk mode's state) live in `src/core` and are host-tested.

**Tech Stack:** C++17, Win32 (ddraw.dll, 32-bit), host tests (`build-host/uagfx_tests`), the ship gate.

**Spec:** the owner's concept doc https://claude.ai/artifact/SxvWxL5BM2tHtSWAvYPh9J («Управление с клавиатуры:
концепция»), section «Решения (12.11)» = the answers 1-13 chosen at the owner's word «выбери ... сам и приступай».

## Global Constraints

- Client only: no uAthena, server or NPC changes. Walks, attacks and clicks are the packets the mouse and the pad send.
- One key = one game action; Ctrl only for the camera and service keys. No chords for game actions.
- Typing is never stolen: a non-empty chat line takes arrows, Space and Tab; letters type as now unless the walk
  mode is on and the chat is closed.
- The game's keys stay: F1-F9, F12, Alt+letters, Alt+0-9, Ctrl+1-9, Insert, Esc, the game's battle mode (/bm).
- Taken already: Ctrl+Tab (the new minimap), Ctrl+` (the effects console), Tab in the chat's words field (channel).
- Every new switch: a schema row on «Інтерфейс», strings uk/ru/en, live config; UI names quoted from strings.cpp uk.
- New lines <= 120 columns (diffs 121); 32/64-bit builds with no warnings; host tests green; ship through gship.sh.
- Betas only (3.0.18-beta.N); notes uk/ru/en per beta; nothing seen on Windows here - each beta's notes say what
  to check.

## Review Focus

1. Focus lost (Alt+Tab, a click in another program) with an arrow held: the character stops, no key stays held.
2. A chat line with text: arrows, Space and Tab edit it; nothing walks or acts.
3. A real pad's stick held together with arrows: the stick wins while it is out of its dead zone.
4. The pad switched off with Back, or no pad at all: the keyboard still walks and acts.
5. The arrow let go on a tick with no pad: the stop step is still sent (the character does not run on 5 cells).
