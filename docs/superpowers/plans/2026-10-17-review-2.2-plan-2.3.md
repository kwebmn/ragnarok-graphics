## A. Ошибки и глюки

### A1. floor_reflect_ps: ранний выход на разрыве глубины убирает и потемнение мокрой земли — ОШИБКА в 2.2.2
`src/win/gpu/shaders.cpp` ~2284: `if (max(breakX, breakY) > 0.03 * p.z) return float4(0,0,0,0);` стоит до
вычисления `dark = 0.16 * flat * twinY`. В дождь (twinY > 0) все пиксели пола затемнены, а пиксели у края ямы —
нет: светлые крапинки/линии ровно там, куда направлено исправление. Старый выход `flat <= 0` был безопасен,
потому что там dark = 0.
Исправить: при разрыве возвращать только затемнение — `float4(0,0,0, twinY > 0 ? 0.16 * twinY : 0)` (пол считать
плоским), отражение `a` = 0. **S, риск низкий. Сделать до выпуска 2.2.2.**

### A2. relief(): `clamp(gs, -1.5, 1.5)` — мёртвый код
Выход `clamp(dot(n, light) / light.z, 0.7, 1.1)` насыщается уже при |gs| ≈ 0.03–0.05 (при силе 100 %:
gs = 0.05 → 1.24 → 1.1). Ограничение на 1.5 ни одного пикселя не меняет; из всей правки работает только `even`.
Текст коммита («наклон ограничен») не соответствует делу. Варианты: убрать clamp (честно) или ограничить там, где
это что-то меняет (≈0.2–0.3) и смягчить кривую — но это изменит вид рельефа везде, надо смотреть в игре.
**S, риск: визуальный.**

### A3. floor_reflect_ps: порог разрыва 0.03·z великоват для лестниц RO
`min()` двух соседей ловит только одиночные пиксели пола (оба соседа вне пола) — это и есть случай «нормаль
наугад», так что сама идея верна. Но ступени 5–10 единиц при z 400–600 дают скачок 0.01–0.03·z — под порогом, и
узкие ступени Башни часов будут мигать дальше. Порог брать относительно собственного наклона пола (например,
> 4 × меньшей разницы или > 2 «следов пикселя»), и гасить `a` плавно, а не обрезать. **S, проверить в игре на
c_tower2.**

### A4. Четыре независимых «грань вырожденная?» — одна причина, четыре порога (главная причина бликов)
В shade(): `even = saturate(min(|T|,|B|)·4 − 0.4)` (2.1.7) и `stretch = 1 − saturate(min(|T|,|B|)·2.5)`;
в relief(): `even` по отношению площади к квадрату шага; в materialLight(): `facing` по dot(V, N). Каждый гасит
свою часть случаев, грань может пройти один фильтр и провалить другой — отсюда «блики пропадают только с целой
группой Поверхности»: источников не меньше двух (блик материала + рельеф + отражения пола).
Сделать: один коэффициент «качество следа текселя» в shade() из du/dv (или dp1/dp2) — и передавать его в
relief(), materialLight() и на выборку материала; один порог вместо четырёх. Заодно `abs(dot(V, N))` лишний: N уже
повёрнута к камере. **M, риск: визуальный; проверять на c_tower2, gl_church, prontera.**

### A5. Статистика: «перемены» пишутся по сырым строкам файла, а не по действующим настройкам
`Context::watchSettings` → `usage_.change()` берёт `u.applied` из `liveUpdate`, который сравнивает `tokenOf` по
файлу. Когда страница или консоль материализуют набор в «Свои» (пишут все ~88 переключателей), в usage.jsonl
попадают ложные строки: `water 0 -> 1`, `grade 0 -> 1` (в dist эти ключи = 0, а набор их включает), а на сайте
это «Вмикали». Это портит главный показатель, ради которого статистика собиралась.
Сделать: для членов групп сравнивать `effective(was.effects)` и `effective(now.effects)`; строки `preset`,
`group_*`, `*_strength` — как сейчас. Тест в test_live_config/test_usage. **S, риск низкий.**

### A6. Консоль: выбор «Свои» в строке качества не материализует набор (страница — да)
`Console::change`: для `effects.preset` → custom пишется только `preset = custom`; переключатели остаются сырыми
из файла, и картинка скачком меняется на «что было в ini». Страница делает `makeCustom()` (все переключатели +
tier, одной записью). Сделать так же в консоли — лучше общей функцией (см. C5). **S.**

### A7. origin/main в локальном репозитории стоит на 0.18.0
Push идёт по явному ssh-адресу, `origin` смотрит на https — tracking-ветка не обновляется, `git status`/`log`
про удалённое состояние молчат. `git remote set-url origin git@github.com:kwebmn/ragnarok-graphics.git` и
`GIT_SSH_COMMAND=... git fetch`. **S.**

### A8. Консоль подписывается на окно игры один раз
`gameProc_` ставится для первого окна; пересоздаст игра окно (смена полноэкранного режима) — новое окно не
перехвачено, клавиши при открытой консоли уйдут в игру. Переподписываться при `game_ != game`. **S, низкий.**

### A9. usage.jsonl: гонка утилиты с драйвером при обрезке файла
`sendUsage` читает файл дважды и пишет `after.substr(taken)` атомарно; строка, дописанная драйвером между вторым
чтением и переименованием, теряется. Окно крошечное и возникает только когда отправка идёт при запущенной игре
(при старте утилиты проверяется `!gameRunning`, наблюдатель шлёт после выхода). Надёжнее схема «переименовать →
отправить → удалить»: утилита переименовывает usage.jsonl в usage.sending.jsonl (драйвер при следующей записи
создаст новый), шлёт его и удаляет; недоотправленный хвост остаётся до следующего раза. **S.**

### A10. Сайт: повторная отправка не распознаётся
Если POST прошёл, а обрезка файла не удалась — строки уйдут второй раз и удвоят минуты. Хранить хэш строки
(unique (install, hash)) или id пакета от утилиты и отбрасывать повторы. **S (миграция + контроллер).**

### A11. Сайт: лимит 6000 строк × 30 запросов/мин с одного IP = до 180 тыс. строк в минуту в БД
Добавить суточный потолок на install (например, 3000 строк) и общий размер таблиц в мониторинг. **S, низкий.**

### A12. Статистика ещё ни разу не прошла путь до конца
В БД 0 отрезков (2.2.1 вышла сегодня, отправка раз в день/после игры, нужен ответ «да»). Для проверки с вашей
машины: кнопка «Отправить статистику сейчас» на «Диагностике» (`sendUsage(dir, force=true)` уже есть) и строка
«последняя отправка: дата, N строк» (stats-sent.txt). **S.**

### A13. В статистике не видно, рисует ли 64-битный мост
`api` = d3d12 и для процесса игры, и для uaro-render64.exe. Добавить в отрезок `"remote":0/1` (и `fps_limit`,
`vsync` — иначе fps не истолковать). Это данные для решения C2. **S.**

### A14. Поток отправки статистики не дожидается завершения при выходе утилиты
Записи атомарные, повреждения не будет; остаться может только временный файл. На WM_DESTROY подождать поток до
3 с. **S, низкий.**

### A15. Лог «при следующем запуске: ai.ground», хотя скрытие вида применяется сразу (aiNow)
`liveUpdate` кладёт ключи [ai] в `waiting`, а скрытие делает через `n.aiNow`. Уточнить лог: «скрыто сейчас,
картинки — при запуске». **S, низкий.**

### A16. Загрузка профиля и «Сбросить» теряют [stats]
Профиль — целый ini; после загрузки старого профиля `stats.send` нет → вопрос задаётся снова и генерируется
новый id (на сайте — «новый игрок»). Переносить `stats.send`/`stats.id` при загрузке профиля и сбросе, как
`utility.language`. **S.**

Ответы на вопросы из памятки для ревью: ссылка `r` в `Console::change` после `build()` не используется — порядок
верный; ↻ для видов спрайтов согласован с драйвером (одна копия на все спрайты); сетка травы выровнена по той же
первой вершине, что и `seams::build`; первые кадры без ячеек рисуют траву как раньше — нормально.

## C. Упрощение

### C1. Три описания одних и тех же ключей ini
`parseConfig` (466 строк if-else), `tokenOf` (220), таблица `iniSettings` (483) и ещё ручные списки в

живое применение из неё. Минус ~600 строк и невозможность расхождения схемы с парсером. test_config/test_schema
фиксируют поведение. **M, риск средний — делать по секциям, начиная с [effects].**

### C2. Два рендерера и вариант шейдеров SAFE — решить по статистике
Direct3D 11 (4166 строк) дублирует факелы, тени, материалы, AI-текстуры; `UAGFX_SAFE` — 13 блоков ради
компилятора, который не берёт новые конструкции. Через 30 дней статистики: доля `api = d3d11` и доля SAFE
(добавить строку в лог/статистику). Если доли ничтожны — заморозить D3D11 (без новых эффектов, объявить в
заметках) и убрать SAFE. **Решение, затем M–L.**

### C3. `Renderer::Impl` — 321 поле, функции по 400–550 строк
applyTorches 555, draw 411, applyActorShadows 252, composite 187; `effectPass` имеет 61 вызов и растущий список

отдельная структура» (как уже сделано для ground cells/hills), параметры effectPass — в `struct PassArgs`,

### C4. Девять копий «записать во временный файл + MoveFileEx»

### C5. Страница эффектов и консоль дублируют логику «набор → свои» и «переключатели как у набора»

### C6. Запись uaro-graphics.ini из драйвера двумя путями, без защиты от одновременной записи утилитой

### C7. Мёртвые тексты не ловятся
