# uaRO Graphics — этап 6: чёткий текст (уточнение спецификации)

Основание: спецификация v1 `2026-10-13-uaro-graphics-design.md` (§4.8 — замысел, §6 — ключ `crisp_text`, §9 п. 6),
уточнение этапа 3 `2026-10-13-stage3-resolution-design.md` (масштаб `k`, правило покрытия, выборка интерфейса),
исследование клиента `docs/research/text.md`. Документ заменяет §4.8 спецификации v1. У клиента нет отдельных текстур
с текстом: каждая текстура интерфейса — плитка целого окна, где вместе картинки, рамки и текст. Поэтому вместо
«двойника текстуры текста» строится двойник всей картинки окна. Версия — 0.5.0.

## 1. Цель

- Весь текст, который игра пишет через GDI, на экране рисуется в настоящих точках окна: чат и поле ввода, окна
  (инвентарь, умения, статус, магазины, диалоги NPC, книги, квесты), кнопки, списки, подсказки, имена над головами. У
  пользователя (175 %) это Arial высотой ≈ 26 точек со сглаживанием вместо растянутого 15-точечного.
- Рамки, линии и заливки окон — ровными блоками на границах точек игры, без размытия фильтра интерфейса. Картинки окон
  (скины, иконки, анимированные значки) — увеличенные, как в 0.4: своих картинок высокого разрешения у игры нет.
- Не меняется:
  - размеры и места окон;
  - раскладка игры: переносы строк, обрезка «...», выделение, курсор поля ввода (буквы крупнее и чётче, стоят на тех же
    местах);
  - цифры урона и прочие числа-спрайты, растровые шрифты (таймеры, рейтинги), подпись на скриншоте;
  - скриншоты — размера игры.
- Работает только при `k > 1` (масштаб Windows или `render_scale` больше 100 %); при `k = 1` — как 0.4.
- `[display] crisp_text = 1` по умолчанию. Pause (клавиша сравнения) выключает и чёткий текст — вместе с остальными
  улучшениями.
- Другая версия exe или любое несовпадение при проверке — функция выключается сама (одна строка в логе), остальное
  работает как в 0.4.

## 2. Как игра рисует текст (`docs/research/text.md`)

### 2.1 Картинка окна

`CDCBitmap` (vtable `0x6956EC`, 0x2C байт) — memory DC и 32-битная top-down DIB ровно размером с окно:

| Поле | Что |
|---|---|
| `+0x04` / `+0x08` | ширина / высота |
| `+0x0C` | HDC |
| `+0x10` | HBITMAP |
| `+0x18` | точки, шаг `w·4` |
| `+0x1C` | байт «изменена»: ставят все записи и GetDC, снимает загрузка |
| `+0x24` / `+0x28` | список плиток (`std::list<CTexture*>`) и их число |

- **Создание.** Фабрика `FUN_00404d50`: `new`, затем конструктор, затем `Clear(NULL, 0xFFFF00FF)` через vtable.
  Конструктор вызывает `CreateCompatibleDC` из `0x402E77` и `FUN_00403960`. Та вызывает
  `CreateDIBSection(NULL, &bmi, DIB_RGB_COLORS, &this->bits, NULL, 0)` из `0x403A10`. Оба места — единственные в exe.
- **Удаление** — через слот 0 vtable. `UIWindow::Create` и `Resize` удаляют старую картинку и создают новую; облачка с
  именами делают это при каждой смене текста.

### 2.2 Запись в картинку

Запись идёт только методами vtable (слоты 2 и 4–9 игра вызывает только через неё) и через GDI на её DC:

| Слот | Адрес | Что |
|---|---|---|
| 0 | `0x402EB0` | деструктор: плитки, `SelectObject`, `DeleteObject`, `DeleteDC` |
| 1 | `0x403780` | увеличение DIB (вызовов нет) |
| 2 | `0x402FF0` | GetDC: ставит «изменена», отдаёт HDC |
| 3 | `0x403010` | ReleaseDC: ничего не делает |
| 4 | `0x4037C0` | CopyPixels(x, y, w, h, src32, key). Без обрезки. С ключом пропускает ровно `0xFFFF00FF`. Строку обрывает на точке назначения `0x00000000`. |
| 5 | `0x4030E0` | CopyFrom(x, y, w, h, дочерняя). Пропускает ровно `0xFFFF00FF`. При x ≥ W или y ≥ H (в том числе отрицательных — сравнение беззнаковое) — ничего. Иначе `w`, `h` обрезаются по правому и нижнему краю. |
| 6 | `0x4031B0` | спрайт ACT/SPR (палитра, RLE) |
| 7 | `0x403460` | копия из текстуры A1R5G5B5 с целым увеличением (анимированные значки) |
| 8 | `0x403020` | Clear(RECT* или NULL, COLORREF). Заливает `[left, right) × [top, bottom)` без обрезки. |
| 9 | `0x403880` | Draw(x, y, w, h, argb): если изменена — загрузка плиток (`FUN_00403a40`), затем квад на каждую плитку |

GDI на DC картинки:
- `TextOutW` — вызов `0x40673F`. Ещё два места, `0x4068E4` и `0x4070B1`, работают только для `"|XY"`; у langtype 14
  их нет.
- `FillRgn` — вызов `0x4CB441`: треугольники `FUN_004cb3e0`.
- `SetTextAlign`, `ExtTextOut*` и функции областей обрезки exe не импортирует. Поэтому выравнивание — TA_TOP|TA_LEFT,
  позиция — целый верхний левый угол ячейки, а обрезка — только по краям DIB. Списки прокручиваются рисованием при
  отрицательном x.
- Обводка — 5 вызовов `TextOutW` со сдвигами ±1, тень — 2.
- Строку `TextOutW` получает в общем буфере игры (`0x6EC084`).

### 2.3 Шрифты и раскладка

- **Шрифты** — `CreateFontA(h, 0, 0, 0, 400|700, 0, 0, 0, charset, 0, 0, NONANTIALIASED_QUALITY, 0, face)`, кеш на всё
  время игры. У uaRO (langtype 14) — Arial, RUSSIAN_CHARSET, высота +3 (12 → 15). Шрифт выбирается в DC перед каждым
  `TextOutW`.
- **Раскладка** — мелким шрифтом (`GetTextExtentPoint32W`): выравнивание, переносы, «...», ширина облачков, курсор и
  выделение.

### 2.4 Окна

`UIWindow`:
- поля: дети — список `+0x0C`; x/y относительно родителя — `+0x14`/`+0x18`; w/h — `+0x1C`/`+0x20`; «изменено» —
  `+0x24` (его ставит `Invalidate`); картинка — `+0x28`.
- `DoDraw`: изменённое окно рисует себя (`OnDraw`), затем детей, затем копирует себя в картинку родителя (`CopyFrom`).
- Окна верхнего уровня — список `UIWindowMgr` (`0x727ED8 + 0x38`). Текст попадает на экран только через них. Имена и
  облачка над головами — тоже отдельные окна верхнего уровня.

### 2.5 Плитки

- Загружаются только картинки окон верхнего уровня. `FUN_00403a40`:
  - плитки до 256×256 создаются при первой загрузке, по строкам: `tx`, `ty` — кратные 256;
  - всем точкам DIB ставится байт альфы `0xFF` (GDI пишет `0x00RRGGBB`);
  - каждая плитка загружается целиком (`CTexture::Update`), 32 бита → A1R5G5B5;
  - точка, у которой пятибитный цвет — пурпурный (R ≥ 248, G ≤ 7, B ≥ 248), становится прозрачной.
- Плитка рисуется квадом точка в точку с целыми углами `(x+tx, y+ty)` через `CTexture::Draw` (`CTexture +0x0C` —
  `IDirectDrawSurface7*`). Цвет вершин — `(альфа окна << 24) | 0xFFFFFF`, смешивание SRCALPHA/INVSRCALPHA, alpha
  test ≥ 1.
- Поле ввода в фокусе игра перерисовывает каждый кадр, и его окно верхнего уровня загружается каждый кадр.

## 3. Двойник: сетка

- **Масштаб.** `K` — масштаб двойников: `k`, который был бы при включённых улучшениях (уточнение этапа 3 §3; Pause его
  не меняет). Двойники строятся и ведутся при `K > 1`, показываются при `k = K`.
- **Размер.** Картинка окна `W × H` → двойник `W' × H'`, `W' = floor(W·K)`, `H' = floor(H·K)`, RGBA8 с premultiplied
  alpha.
- **Блоки.** Точка игры `g` занимает в двойнике точки `[floor(g·K), floor((g+1)·K))` по каждой оси. Блок не меньше
  одной точки (`K ≥ 1`), блоки идут сплошь.
  - «Увеличить точку» — залить её блок её цветом.
  - Точка, прозрачная по правилу загрузки игры (пятибитный пурпурный, §2.5), становится прозрачной (0, 0, 0, 0).
  - Цвета — восьмибитные, как в DIB; игра на экране показывает их пятибитными.
- **Показ.** Окно в точке игры `x0` покрывает точки цели `[ceil(x0·k), ceil((x0+W)·k))` (правило покрытия этапа 3).
  Точка цели `p` показывает точку двойника `min(p − ceil(x0·k), W' − 1)`. Отсюда:
  - каждая точка цели берёт ровно одну точку двойника — чётко, без пересчёта;
  - мест на экране не меньше `W'` (`ceil(a + b) − ceil(a) ≥ floor(b)`), поэтому ни одна точка игры не теряется;
    лишняя точка экрана, если она есть, повторяет последний столбец (строку);
  - содержимое сдвинуто относительно идеального увеличения меньше чем на точку цели — незаметно;
  - перетаскивание окна и движение имён над головами меняют только целый сдвиг, двойник не перестраивается.
- **Плитки.**
  - Плитке `(tx, ty, tw, th)` нужна текстура-двойник с точками двойника `[floor(tx·K), min(ceil((tx+tw)·K), W'))`, по
    `y` так же.
  - Квад плитки покрывает точки цели `[ceil((x0+tx)·k), ceil((x0+tx+tw)·k))`. Им нужны точки двойника только из этого
    отрезка: `ceil(a + b) − ceil(a) ∈ [floor(b), ceil(b)]`.
  - Точка цели `p` берёт тексель `min(p − O, размер − 1)`, где `O = ceil(x0·k) + floor(tx·K)`.
  - У всех плиток окна один сдвиг `ceil(x0·k)`, поэтому соседние плитки стыкуются без шва.
- **Дочерние окна.** При `CopyFrom` в точку `(x, y)` родителя точки двойника родителя `[floor(x·K), floor((x+w)·K))`
  берут точки двойника дочерней `min(n − floor(x·K), floor(w·K) − 1)`.
  - Левый и верхний край ребёнка совпадают с блоками родителя.
  - Правый и нижний не теряются: `floor(a + b) − floor(a) ≥ floor(b)`.

## 4. Повторение записей игры

Каждая подмена сначала вызывает оригинал игры — мелкая картинка остаётся ровно такой, как без драйвера, — затем
повторяет запись в двойнике.

Для каждой картинки хранится «копия»: мелкая картинка в том виде, который отражён в двойнике. «Сверка» прямоугольника:
точки DIB, которые отличаются от копии по цвету, увеличиваются в двойник, и копия обновляется. Байт альфы не
сравнивается: игра меняет его сама перед загрузкой.

- **Clear(rect, color).** Блоки точек `[left, right) × [top, bottom)` в пределах картинки (NULL — всей картинки)
  заливаются новыми мелкими точками.
  - Заливка стирает и края крупных букв. Сверка по изменившимся точкам этого не сделала бы.
  - Игра прямоугольник не обрезает. То, что вышло за края по строкам, ловит сверка при `Draw`.
- **FillRgn(hdc, rgn, brush)** — так же для всех точек области (`GetRegionData`).
- **CopyFrom(x, y, w, h, дочерняя)** — с обрезкой игры (§2.2). Сначала сверка дочерней целиком. Затем её двойник
  кладётся «поверх» (premultiplied) в блоки области по сетке §3: прозрачные точки дочерней оставляют родителя, края
  крупных букв ложатся на него.
- **TextOutW(hdc, x, y, s, n)** на DC картинки окна. Какой картинке принадлежит DC, драйвер знает по GetDC и по
  созданию DIB.
  - Места букв — из раскладки игры. `GetTextExtentExPointW` мелким шрифтом на DC игры даёт `a_i` — ширину первых `i`
    букв. Буква `i` ставится в `floor((x + a_i)·K)` — в начало блока той точки игры, где стоит мелкая буква.
  - Базовая линия — `floor((y + ascent)·K)` (`ascent` мелкого шрифта, `GetTextMetricsW`).
  - Крупный шрифт — тот же, что выбран в DC (`GetObject`: гарнитура, кодировка, жирность), высотой
    `round(lfHeight·K)`. Покрытие букв — `GetGlyphOutlineW(GGO_GRAY8_BITMAP)`, 65 оттенков серого.
  - Цвет — `GetTextColor(hdc)`. Буквы кладутся «поверх» в двойника этим цветом, покрытие служит альфой. Обрезка — по
    краям двойника, как GDI по краям DIB.
  - До вызова — сверка прямоугольника строки с запасом на высоту шрифта. После вызова копия в нём обновляется из DIB
    без увеличения. Мелкие буквы в двойник не попадают, в нём — крупные.
  - DC с другим выравниванием, наклонный шрифт или DC не картинки окна — запись идёт как «прочие» (ниже).
- **Прочие записи** — после оригинала идёт сверка:
  - CopyPixels (слот 4) — прямоугольник из аргументов;
  - спрайт (слот 6) и копия из текстуры (слот 7) — вся картинка.

  Точки, которые запись не изменила, двойника не трогают: края крупных букв под прозрачными частями картинки остаются.
- **Кеш букв.** Покрытие и метрики буквы по ключу (шрифт, высота, жирность, `K`, буква), LRU до 16 МБ. Окно чата
  перерисовывается каждый кадр, а буквы растрируются один раз.
- **Страховка.** При `Draw` (слот 9) изменённого окна — сверка картинки целиком (у дочерних — сверка в `CopyFrom`).
  Запись в DIB неизвестным путём попадает в двойник увеличенной: окно в этом месте не чёткое, но верное. В лог — одна
  строка на размер окна.

## 5. Перехваты и жизнь двойников

- **Что подменяется:**
  - 10 записей vtable `0x6956EC` в `.rdata`: `VirtualProtect` на запись, подмена, прежняя защита;
  - три импорта `uaRO.exe` из `gdi32.dll`: `TextOutW`, `FillRgn`, `CreateDIBSection`.

  Чужие вызовы GDI (ROExt, Windows) не затрагиваются.
- **Проверка перед подменой:**
  - в 10 записях — известные адреса (`0x402EB0` … `0x403880`);
  - каждый из трёх импортов указывает туда же, куда `GetProcAddress` из `gdi32.dll`.

  Любое несовпадение — `crisp text: off (<что>)`, и ничего не подменяется.
- **Когда.** Подмена ставится при первом `DirectDrawCreateEx` рендера uaRO при `crisp_text = 1`: exe к этому времени
  загружен целиком. При закрытии рендера записи и импорты возвращаются, двойники удаляются.
- **Двойник и копия.**
  - Создаются при первой записи, увиденной при `K > 1`, из текущей DIB (увеличением) и ищутся по `this`.
  - `CreateDIBSection` из `0x403A10` (адрес возврата проверяется) даёт `this = ppvBits − 0x18`. Новая DIB — новый
    двойник, даже если память старой картинки досталась новой.
  - Деструктор (слот 0) удаляет двойника, копию и текстуры плиток.
- **Смена `K`** (другой монитор, размер окна, `render_scale`) и **первое `K > 1`** после запуска.
  - Двойники удаляются. В начале следующего показа, вне рисования игры, драйвер ставит признак «изменено» (`+0x24`, как
    `Invalidate`) всем окнам — верхнего уровня (`0x727ED8 + 0x38`) и их детям рекурсивно.
  - Игра перерисует окна, и двойники построятся заново. До перерисовки окно показывается как в 0.4.
  - Pause `K` не меняет: двойники ведутся дальше, и при повторном нажатии текст сразу чёткий.
- **Поток.** Интерфейс игра рисует в главном потоке, рендер драйвера работает там же.

## 6. Плитки и показ

- **Загрузка и выбор.**
  - Подменённый `Draw` (слот 9) отмечает картинку текущей, запоминает «изменена» и вызывает оригинал.
  - Внутри оригинала игра рисует плитки. Плитку текущей картинки драйвер узнаёт по текстуре стадии 0: это
    `CTexture +0x0C` из списка `+0x24`, а номер в списке даёт `tx`, `ty`.
  - Если картинка была изменена или у плитки ещё нет текстуры-двойника, драйвер сначала загружает её (§3), затем
    записывает рисование плитки с двойником. Так первый же кадр нового облачка или подсказки — чёткий.
- **Рисование** — новый режим шейдера интерфейса `uiMode = 3`:
  - тексель `min(floor(SV_Position.xy) − O, размер − 1)` читается `Load`;
  - premultiplied → обычный цвет, дальше — как текстура стадии 0: цвет вершин даёт альфу окна, смешивание и alpha test
    — как у игры;
  - `x0` — левый край квада в точках игры минус `tx` (по `y` — верхний край минус `ty`);
  - `O` и размер текстуры-двойника передаются в константах рисования.
- **Без двойника.** Если двойника нет (в том числе не хватило памяти или текстуры), `K ≠ k` или квад не плитка
  текущей картинки, плитка рисуется как в 0.4 (фильтр интерфейса этапа 3).
- **Скриншоты.** Игра читает кадр размера `L`, поэтому текст на скриншотах сглаженный (уменьшение кадра).

## 7. Настройки и лог

```ini
[display]
; 1 = text and window lines at the window's real pixels (only when the game is enlarged, k > 1); 0 = as version 0.4
crisp_text = 1
```

Ключ перенесён из `[quality]` в `[display]` (§6 спецификации v1 исправлен): он относится к интерфейсу, как
`ui_filter`. Установка и обновление дописывают его в существующий ini, как `sharpen` в 0.4.0.

Лог:
- `crisp text: on` / `crisp text: off (<причина>)`;
- при смене `K` — `crisp text: k X, N windows redrawn`;
- страховка — `crisp text: a WxH window changed outside the known calls` (одна строка на размер);
- раз в 30 секунд в строке статистики — двойники (число, МБ) и буквы в кеше.

## 8. Проверка

- **Linux, ядро** (модули без Win32):
  - сетка: размеры, блоки, отрезки плиток, `O`, область `CopyFrom`;
  - эталонный растеризатор: при дробных `k` (1,25, 1,5, 1,75, 2,625) и любом `x0`, в том числе отрицательном, каждая
    точка цели окна берёт ровно одну точку двойника, каждая точка игры видна, стыки плиток без шва;
  - двойник: увеличение по правилу прозрачности игры, заливка прямоугольника и области, «поверх», `CopyFrom` с обрезкой
    игры и отрицательными координатами, сверка с копией, страховка;
  - текст: места букв из ширин игры ×`K`, базовая линия, обрезка по краям, «поверх» с покрытием (на буквах-образцах);
  - кеш букв (LRU, предел);
  - проверка записей vtable и импортов на образцах.
- **Windows:** сборка без предупреждений, `check_dll`, HLSL — glslang, финальное ревью.
- **Чек-лист 0.5.0 у пользователя:**
  - чат: набор, курсор, выделение, русский текст, прокрутка, цвета, обводки;
  - окна: инвентарь, умения, статус, магазин, NPC, квесты, книга;
  - подсказки, имена над головами, перетаскивание окон;
  - Pause, `render_scale = 150`, fps, лог.

## 9. Риски

| Риск | Что делаем |
|---|---|
| Крупный Arial шире или уже, расстояния между буквами чуть неровные | каждая буква — на месте мелкой; проверка у пользователя |
| Окно чата перерисовывается каждый кадр — работа CPU и загрузка плиток | кеш букв; заливки построчно; загрузка ~1 МБ на кадр |
| Запись в картинку окна неизвестным путём | страховка при `Draw` и `CopyFrom` (§4) |
| Запись того же цвета поверх края крупной буквы (картинка поверх текста) | край может остаться; случай редкий, проверка у пользователя |
| Цвета окон чуть точнее, чем в 0.4 (8 бит вместо 5) | заметно только при сравнении через Pause; прозрачность — точно как у игры |
| Другая версия exe, другой langtype | проверка адресов и импортов; шрифт берётся из DC игры |
| После смены `K` окно ещё не перерисовано | показывается как в 0.4 до перерисовки |
| Память | двойники и копии — `(K² + 1)·4` байта на точку картинки, десятки МБ |

## 10. Вне этапа 6

- цифры урона и спрайтовые числа;
- растровые шрифты;
- подпись скриншота (`TextOutA` на кадре);
- окно IME Windows (его рисует Windows);
- картинки окон высокого разрешения;
- текст при `k = 1`.
