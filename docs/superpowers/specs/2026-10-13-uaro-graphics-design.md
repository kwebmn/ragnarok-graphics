# uaRO Graphics — свой графический драйвер для легаси-клиента uaRO

Дата: 2026-10-13 · Статус: черновик на ревью · Репозиторий: `kwebmn/ragnarok-graphics`

## 1. Цель

Заменить dgVoodoo своим драйвером: `ddraw.dll` принимает вызовы DirectX 7 клиента `uaRO.exe` и рисует их через
Direct3D 12. К драйверу — отдельная утилита настроек «uaRO Graphics Settings».

Проект делится на части, у каждой своя спецификация и план:

| Часть | Что | Статус |
|---|---|---|
| 1 | Ядро драйвера (DX7 → D3D12) | **эта спецификация** |
| 2 | Утилита настроек | **эта спецификация** |
| 3 | Генерация кадров (DLSS Frame Generation, Reflex) через 64-битный процесс-рендер | позже |
| 4 | Режим RTX Remix (выход в D3D9 с 3D-миром) | позже |

HD-текстуры и HD-спрайты в проект пока не входят (решение пользователя).

**Критерии успеха v1**
- Ставится копированием файлов в папку клиента; `uaRO.exe` не меняется. dgVoodoo остаётся рендером по умолчанию,
  uaRO Graphics включается в утилите; вернуть dgVoodoo — одна кнопка.
- С выключенными улучшениями картинка совпадает с dgVoodoo на всех экранах: заставка Bink (если есть), логин, выбор
  персонажа, игра, загрузка, эффекты, скриншоты. Интерфейс и текст не «плывут».
- Работают улучшения v1: мир в разрешении монитора и масштаб интерфейса; MSAA, суперсэмплинг, анизотропия;
  HDR10; чёткий текст.
- При любой ошибке драйвера игра всё равно запускается (откат на dgVoodoo или системный DirectDraw), а лог
  объясняет, что произошло.
- Проверочная машина: RTX 5060 Ti 16 GB, Windows 10/11.

## 2. Исходные факты (декомпиляция 2026-10-13, ключевые места сверены вручную)

**Клиент** — `/root/BornRok/winEXE/uaRO.exe` (тот, что у игроков), PE32 i386, Sakexe 2007. Декомпиляция Ghidra:
`/root/BornRok/winEXE/decomp/uaRO_decomp.c`, ниже `L…` — её строки.

**Создание.** Из `DDRAW.dll` импортируется только `DirectDrawCreateEx`; `LoadLibrary` для ddraw/d3dim нет.
Объект рендера `C3dDevice` — глобальный `0x6ebe18` (+2c primary, +30 back = RT, +38 Z, +3c device, +40 DD7,
+44 D3D7, +1e0 sysmem-копия экрана). `DirectDrawCreateEx(IID_IDirectDraw7)` L2859 → `QueryInterface(IID_IDirect3D7)`
L2951 → `CreateDevice(GUID из реестра)` L2956; GUID сравнивается только с HAL/TnLHal (где держать Z-буфер).

**Используемые методы.**

| Интерфейс | Методы |
|---|---|
| IDirectDraw7 | SetCooperativeLevel (0xC08 окно / 0xC13 полный экран, L2878), SetDisplayMode (только полный экран, L3094), CreateSurface, EnumTextureFormats (через D3D7, L20928), GetCaps, WaitForVerticalBlank (L3352), RestoreAllSurfaces (L3408), FlipToGDISurface (перед окнами ошибок, L2605), CreateClipper |
| IDirectDrawSurface7 | Flip(WAIT) (L3345), Blt (present в окне, копии RT↔sysmem, COLORFILL, растягивание для мип-уровней и Bink), BltFast SRCCOLORKEY (только картинки больше макс. размера текстуры), Lock/Unlock, GetDC/ReleaseDC (на back buffer: подпись скриншота и FPS), GetAttachedSurface, AddAttachedSurface (Z), SetClipper |
| IDirectDrawClipper | SetHWnd |
| IDirect3D7 | CreateDevice, EnumZBufferFormats (обратный вызов `0x404530` берёт 16 бит) |
| IDirect3DDevice7 | GetCaps, SetViewport (раз), Clear TARGET\|ZBUFFER (L3374), BeginScene/EndScene (один раз за кадр), SetRenderState (~61 место), SetTextureStageState (~160 мест), SetTexture (стадии 0–1), DrawPrimitive / DrawIndexedPrimitive (TRIANGLELIST/STRIP), SetTransform/SetLight (ни на что не влияют), EnumTextureFormats |

Не используются: палитры, gamma control, SetColorKey, vertex buffers (мёртвый код), stencil, LIGHTING.

**Отрисовка.** Все живые вызовы — FVF `0x1C4` (XYZRHW|DIFFUSE|SPECULAR|TEX1) или `0x2C4` (то же + TEX2, лайтмап
земли). Мир проецируется на CPU (`ProjectVertex 0x412cb0`, L15059). Состояния: ZENABLE, ZWRITEENABLE,
ZFUNC LESSEQUAL, альфа-тест GREATEREQUAL (ALPHAREF 0xCF или 1), блендинг SRCALPHA/INVSRCALPHA и ONE/ONE плюс
значения эффектов из данных (L11843), CULLMODE NONE/CW, COLORKEYENABLE 1, вершинный туман LINEAR (фактор в
альфе specular, только если в caps есть FOGVERTEX, L9383/L14459). Стадия 0 — в основном MODULATE, линейная
фильтрация, CLAMP; стадия 1 — лайтмап (MODULATEALPHA_ADDCOLOR, BORDER) и 16 пресетов эффектов (L13136–13400).

**Кадр.** Один BeginScene/EndScene (`0x40d8d0`, L10986). Всё рисуемое копится в списки (`AddRP 0x412020`) и
сбрасывается `0x40e4d0` в фиксированном порядке: непрозрачное с альфа-тестом → земля с лайтмапом → полупрозрачное
→ аддитивное → эффекты → **интерфейс после `SetRenderState(ZENABLE, 0)` (L11851)**. Интерфейс и курсор — D3D-квады.

**Текстуры.** Managed, степени двойки, опционально мип-уровни (через растягивающий Blt). Форматы — только
A1R5G5B5 и A4R4G4B4; если их нет в EnumTextureFormats, клиент показывает ошибку (L20884). Пурпурный цвет клиент
сам превращает в прозрачность на CPU (L20413). Все загрузки картинок с CPU идут через одну функцию
`CTexture update 0x4176c0` (32-битные пиксели → A1R5G5B5; прямой вызов только в калибровке L3771, остальные
виртуальные).

**Поверхности.** Окно: primary + клиппер + offscreen back buffer с 3DDEVICE, показ — Blt primary←back после
WaitForVerticalBlank. Полный экран: цепочка FLIP|COMPLEX с одним back buffer. Плюс sysmem-копия экрана, Z-буфер
(16 бит, без stencil, присоединён к RT), offscreen с пурпурным ключом для больших картинок. Формат экрана — 565, 555
или 32 бит (L3524–3545); COLORFILL кодирует цвет в формате экрана, даже для текстур (L20225).

**Чтение кадра назад.**
- Калибровка при запуске (`FUN_004051f0`, L3767–3935): до 65 536 мелких квадов, чтение через Blt + Lock, по
  результату — сдвиг UV для всех 2D-квадов (L20679). Растеризация и фильтрация должны совпадать с DX7.
- Каждый кадр RT блокируется (L12860), но память не читается.
- Скриншоты; затемнение при смене режима (RT → sysmem, ~255 мс квад затемнения, обратно; L206339–206361);
  эффект галлюцинации (Lock back buffer после EndScene, L13909–14040).
- Back buffer должен сохранять содержимое после показа.

**Показ.** Полный экран — Flip(WAIT); окно — vsync + Blt; экран загрузки — Blt без vsync (L3340); Bink — растягивающий
Blt в клиентскую область (L224765), только если есть `openning.bik`.

**Завершение.** Ненулевой счётчик ссылок device/DD7 при выходе → MessageBox (L2663–2706). Unlock незаблокированной
поверхности перед окном ошибки (L2603) не должен падать.

**Реестр.** `HKEY_LOCAL_MACHINE` (L458340+), путь ключа собирается во время работы (указатель `0x6bd38c` →
`0x70ef24`; в exe есть строки `Software\Gravity Soft\Ragnarok` и `Software\Gravity Soft\RoClient`). Значения:
ISFULLSCREENMODE, WIDTH, HEIGHT, BITPERPIXEL, GUIDDRIVER, GUIDDEVICE, DEVICENAME, TRILINEARFILTER, SPRITEMODE,
TEXTUREMODE. 32-битный клиент без манифеста → на 64-битной Windows читает `WOW6432Node`, возможна виртуализация
UAC (`VirtualStore`).

**Текст.** 32-битный top-down DIB section (L2406), шрифты `CreateFontA` (L4385, 4614, 5416, 5500), вывод
`TextOutW` (L4933, 4982, 5426), измерение `GetTextExtentPoint32W`. Из DIB текст попадает в текстуру через
`0x4176c0`. `TextOutA` (L12977) — только подпись скриншота и FPS.

**Окружение у игроков.** dgVoodoo 2.55 (`DDraw.dll` + `D3DImm.dll`, вывод D3D11). ROExt как `dinput.dll` ставит
inline-перехват на `DirectDrawCreateEx`, `CreateWindowExA`, `PeekMessageA`. Геймпад uaRO Pad (`dinput.dll`) —
по желанию.

**Тулчейн.** MinGW-w64 i686 GCC 12: есть `ddraw.h`, `d3d.h`, `d3d12.h`, `dxgi1_6.h`, `d3dcompiler.h`, `libd3d12.a`.

**Внешние ограничения (для частей 3–4).** DLSS Frame Generation в Streamline — только D3D12; библиотеки DLSS —
только x64. RTX Remix принимает D3D8/9 с фиксированным конвейером и сам содержит мост 32→64.

## 3. Архитектура

### 3.1 Файлы в папке клиента

| Файл | Что |
|---|---|
| `ddraw.dll` | драйвер uaRO Graphics (32 бит) |
| `uaro-graphics.ini` | настройки (с комментариями) |
| `uaro-graphics.log` | лог |
| `uaro-graphics-pipelines.txt` | ключи конвейеров, встреченных в игре: строятся заранее при запуске (кэш с 0.4.1, удаляется `uninstall.bat`) |
| `uaro-graphics.exe` | утилита «uaRO Graphics Settings» |
| `dgvoodoo\DDraw.dll`, `dgvoodoo\D3DImm.dll` | dgVoodoo, перенесённый в подпапку (для отката) |

### 3.2 Запуск и выбор рендера

1. Клиент грузит наш `ddraw.dll`. `d3d12.dll`, `dxgi.dll`, `d3dcompiler_47.dll` загружаются динамически — DLL
   грузится и на Windows 7.
2. `DirectDrawCreateEx` читает `[renderer] backend` (`dgvoodoo` по умолчанию / `uaro`).
3. `uaro`: Windows 10+, создаётся устройство D3D12 FL 11_0+ → наша реализация. Иначе — откат с записью в лог.
4. Откат: `dgvoodoo\DDraw.dll` (загрузка из подпапки — проверить на ПК пользователя; если dgVoodoo так не
   работает, утилита меняет файлы местами, пока игра закрыта) → системный `ddraw.dll`.
5. Остальные экспорты ddraw (DirectDrawCreate, DirectDrawEnumerate*, DirectDrawCreateClipper и т. д.) пересылаются
   в выбранный запасной ddraw.
6. Экспорт `DirectDrawCreateEx` начинается с пролога горячего патча (`mov edi,edi; push ebp; mov ebp,esp`) и
   переходит в реализацию — inline-перехват ROExt его не ломает.

### 3.3 Слои драйвера

1. **Приём вызовов DX7** (`src/win/dx7`): COM-объекты IDirectDraw7, IDirectDrawSurface7, IDirectDrawClipper,
   IDirect3D7, IDirect3DDevice7 — только методы из §2. Неиспользуемые возвращают `DDERR_UNSUPPORTED` /
   `E_NOTIMPL` и один раз пишутся в лог. Счётчики ссылок честные (MessageBox при выходе).
2. **Модель поверхностей** (`src/core/surface`): у каждой поверхности CPU-память в формате клиента (Lock, Blt,
   BltFast, COLORFILL, растягивание, цветовой ключ — на CPU, тестируется на Linux). Текстуры зеркалятся на GPU
   (загрузка по Unlock/Blt с грязными прямоугольниками). RT и back buffer живут на GPU; CPU-копия — только по
   требованию (§4.3).
3. **Запись кадра** (`src/core/frame`): между BeginScene и показом — список команд: состояния, текстуры по id,
   рисование (вершины копируются в арену кадра), Clear, Viewport, `UIBegin` (первый ZENABLE=FALSE после
   BeginScene), Blt в RT, Present. Чистые данные без указателей, с явными размерами: их можно сохранить в файл
   (§7) и в части 3 передавать в 64-битный процесс.
4. **Рендер D3D12** (`src/win/d3d12`): устройство, очередь, swap chain (flip model, окно или без рамки), кадры в
   полёте, кольцевые буферы загрузки, кеш PSO по ключу состояния, корневая сигнатура (2 текстуры + семплеры +
   константы), шейдеры HLSL (компиляция `d3dcompiler_47` при старте, кеш на диске). Проходы: мир → интерфейс →
   resolve → вывод SDR/HDR → показ. RT клиента — постоянная текстура: содержимое переживает показ.
5. **Перехваты в клиенте** (`src/win/hooks`): IAT-перехваты GDI (`CreateFontA`, `SelectObject`, `SetTextColor`,
   `TextOutW`, `GetTextExtentPoint32W`, `CreateDIBSection`) и перехват кода `0x4176c0` с проверкой сигнатуры, как в
   геймпаде. Не совпала сигнатура — функция выключается, остальное работает.
6. **Настройки, лог, горячие клавиши** (`src/core/config`, `src/win/log`).

## 4. Поведение и функции v1

### 4.1 Режимы экрана и показ
- **Окно**: размер окна — `window_width × window_height` из настроек (0 — размер, заданный клиентом).
- **Полный экран** = окно без рамки на весь выбранный монитор. `SetDisplayMode` задаёт только логическое разрешение,
  режим монитора не меняется. Эксклюзивный режим не используется, Alt+Tab мгновенный, потеря поверхностей
  (`DDERR_SURFACELOST`) никогда не сообщается.
- Flip(WAIT) и WaitForVerticalBlank+Blt → показ с vsync по настройке; Blt экрана загрузки → показ сразу.
- Настройки: VSync, ограничение FPS, разрешение разрывов (для G-SYNC/VRR).

### 4.2 Координаты и масштаб
*Уточнено для этапа 3 в `2026-10-13-stage3-resolution-design.md`: вывод `O` — в настоящих точках окна (масштаб
Windows), формула вершин `x · k + 0.5`, перевод прямоугольников, чтение и запись кадра при масштабе.*
- Логическое разрешение `L` — то, что видит клиент (реестр WIDTH/HEIGHT). Вывод `O` — клиентская область окна.
  Масштаб `s = O / L`, одинаковый по осям; если пропорции не совпадают — поля по краям (утилита подбирает `L` под
  пропорции монитора, чтобы полей не было).
- **Масштаб рендера** `r` (100–200 %): внутренний RT = `O · r`, на выводе уменьшается качественным фильтром
  (суперсэмплинг). Общий множитель вершин `k = s · r`.
- Позиции вершин во внутреннем RT: `x' = (x + 0.5) · k`, `y' = (y + 0.5) · k` (центры пикселей DX7 — в целых
  координатах, DX12 — в половинках). `z` и `rhw` не меняются. Viewport, Clear, прямоугольники Blt в RT
  масштабируются так же.
- **Фильтр интерфейса**: «гладко» (билинейный) или «чётко» (sharp-bilinear в шейдере для квадов интерфейса).

### 4.3 Чтение и запись кадра клиентом
- До первого показа кадра `s = r = 1`: калибровка видит ровно DX7-картинку.
- Lock RT/back buffer возвращает CPU-копию в логическом разрешении, память которой защищена (guard page).
  Реальное чтение с GPU (с уменьшением при `s ≠ 1`) происходит только при первом обращении — ежекадровый Lock
  без чтения ничего не стоит.
- Unlock после записи на CPU (эффект галлюцинации), Blt sysmem → RT (затемнение) → загрузка обратно в RT с
  увеличением.
- Скриншоты читают логическое разрешение.

### 4.4 Текстуры и форматы
- EnumTextureFormats отдаёт только 16-битные форматы, как видеокарты той эпохи (A1R5G5B5, A4R4G4B4, R5G6B5,
  X1R5G5B5), чтобы клиент выбирал то же, что всегда; на GPU всё хранится в RGBA8 (перевод без потерь).
- Формат экрана: поддерживаем 565, 555 и 32 бит (CPU-копии и COLORFILL — в формате экрана); утилита ставит
  BITPERPIXEL = 32. Максимальный размер текстуры сообщаем 4096 (ветка BltFast для больших картинок не включается).
- Мип-уровни: свои у клиента — используются; опция «строить мип-уровни для текстур мира», если клиент их не
  построил.
- Z-буфер на GPU — 24/32 бит независимо от запрошенных 16 (меньше мерцания).

### 4.5 Перевод конвейера
- Таблица соответствия render states и texture stage states → ключ PSO и константы шейдера.
- Пиксельный шейдер эмулирует две стадии DX7 (операции, используемые клиентом, включая
  MODULATEALPHA_ADDCOLOR и 16 пресетов эффектов), альфа-тест, вершинный туман из альфы specular (в caps
  сообщаем FOGVERTEX), режимы адресации CLAMP/WRAP/BORDER.
- COLORKEYENABLE: клиент не задаёт ключ (SetColorKey не вызывается) → ничего не делает, пишется в лог один раз.

### 4.6 Сглаживание и фильтрация
- MSAA 2×/4×/8× для RT кадра (цвет + глубина), resolve перед выводом и перед чтением кадра.
- Alpha-to-coverage для рисования с альфа-тестом при включённом MSAA (сглаживает края спрайтов), опция.
- Анизотропия 2–16× только для мира (до `UIBegin`); интерфейс — с фильтром клиента.

### 4.7 HDR
- Включается, если монитор в HDR (`IDXGIOutput6::GetDesc1`) и опция включена; иначе обычный SDR.
- Swap chain `R10G10B10A2` + HDR10 (PQ, Rec.2020).
- Кадр рисуется в SDR (RGBA8) с маской интерфейса. Проход вывода: sRGB → линейный → «белый лист» (нит) →
  для мира — мягкое растяжение ярких мест до пика (сила — опция) → PQ. Интерфейс — ровно «белый лист».
- Настройки: HDR вкл/выкл, белый лист (по умолчанию 200 нит), пик (по умолчанию из EDID), сила растяжения.

### 4.8 Чёткий текст
Заменено уточнением этапа 6 `2026-10-13-stage6-crisp-text-design.md`: отдельных текстур текста у клиента нет, поэтому
драйвер ведёт двойник высокого разрешения всей картинки окна (перехваты vtable картинки окна и GDI) и рисует плитки
окон из него. Опция вкл/выкл; несовпадение при проверке exe → обычный текст.

### 4.9 Диагностика
- `uaro-graphics.log`: Windows, видеокарта, уровень D3D12, HDR, настройки, каждый неподдержанный вызов
  (один раз), ошибки с HRESULT, откаты.
- Горячая клавиша сохранения кадра (по умолчанию Ctrl+Shift+F12): `captures/frame-NNNN.uagf` (запись кадра +
  текстуры) и PNG вывода.
- Горячая клавиша A/B (по умолчанию Ctrl+F11): улучшения (MSAA, анизотропия, текст, HDR) вкл/выкл на лету.

## 5. Утилита «uaRO Graphics Settings» (`uaro-graphics.exe`)

*Заменено спецификацией этапа 2 `2026-10-13-stage2-settings-utility-design.md` (выпуски 0.6.0–0.6.2).*

- Обычное окно Win32 с вкладками, без фреймворков, манифест (визуальные стили, DPI, `asInvoker`); работает и
  на Windows 7 (там предлагает только dgVoodoo и объясняет, что нужна Windows 10).
- Языки EN (по умолчанию), UA, RU — выбор вверху.
- Вкладки:
  1. **Рендер** — dgVoodoo / uaRO Graphics; проверки: версия Windows, создание устройства D3D12, HDR-монитор,
     что установлено и активно.
  2. **Экран** — окно / без рамки, монитор, размер окна, масштаб интерфейса (100/125/150/175/200 % или свой) с
     подсказкой «клиент 1706×960 → экран 2560×1440».
  3. **Качество** — MSAA, alpha-to-coverage, масштаб рендера, анизотропия, мип-уровни, фильтр интерфейса,
     чёткий текст.
  4. **HDR** — вкл/выкл (неактивно без HDR-монитора), белый лист, пик, сила растяжения.
  5. **Кадры** — VSync, ограничение FPS, разрешение разрывов.
  6. **Диагностика** — подробность лога, открыть лог, горячие клавиши, сброс к умолчаниям.
- «Сохранить», «Сохранить и запустить игру», «Отмена».
- Пишет `uaro-graphics.ini`, сохраняя комментарии (приём `applyIniEdits` из uaRO Pad), и в реестр клиента
  WIDTH/HEIGHT (= монитор / масштаб), BITPERPIXEL = 32, ISFULLSCREENMODE — туда, откуда их реально читает клиент
  (точный путь определяется на этапе 2: HKLM `WOW6432Node` с повышением прав или `VirtualStore` пользователя).
- Переключение рендера — `[renderer] backend` (или замена файлов, если dgVoodoo не грузится из подпапки).
- Пока `uaRO.exe` запущен, файлы не меняются — предупреждение.

## 6. `uaro-graphics.ini` (ключи v1)

```ini
[renderer]
backend = dgvoodoo        ; dgvoodoo | uaro

[display]
mode = auto               ; auto | window | borderless (auto — как просит игра; этап 1B)
high_resolution = 1       ; рисовать в настоящих точках окна (этап 3)
monitor = 0               ; 0 = основной
window_width = 0          ; только для mode = window; 0 = размер, заданный клиентом (масштаб 1)
window_height = 0
ui_filter = sharp         ; sharp | smooth
crisp_text = 1            ; чёткий текст (этап 6)

[quality]
msaa = 4                  ; 0 | 2 | 4 | 8
alpha_to_coverage = 1
render_scale = 100        ; 100–200, %
anisotropy = 16           ; 0 | 2 | 4 | 8 | 16
auto_mips = 1

[hdr]
enabled = 0
paper_white = 200         ; нит
peak = 0                  ; 0 = из EDID монитора
highlight = 50            ; 0–100, %

[frames]
vsync = 1
fps_limit = 0             ; 0 = без ограничения
allow_tearing = 0

[debug]
log = normal              ; normal | verbose
capture_key = ctrl+shift+f12
ab_key = ctrl+f11
```

Масштаб интерфейса в ini не хранится: он равен `O / L`, а `L` утилита пишет в реестр клиента.

## 7. Сборка и тесты

- MinGW-w64 i686, статически (`libgcc`, `libstdc++`), `make`. Цели: `ddraw.dll`, `uaro-graphics.exe`, тесты, zip.
- Структура: `src/core` (переносимая логика), `src/win` (DX7-объекты, D3D12, перехваты, лог), `tools/settings`
  (утилита), `tests/`, `dist/` (ini, README EN/UA/RU), `docs/`.
- Тесты на Linux (свой раннер, как в uaRO Pad): форматы и COLORFILL, поверхности (Lock, Blt, BltFast, ключ,
  растягивание), перевод состояний, запись кадра и её сериализация, масштаб и полпикселя, настройки и ini.
- **Эталонный растеризатор** (CPU, правила DX7: центры пикселей в целых, top-left, перспективно-корректные UV
  через rhw, билинейная фильтрация, две стадии): повтор калибровки клиента (логика `FUN_004051f0` из
  декомпиляции) через наш перевод должен дать тот же сдвиг UV, что на DX7.
- Сохранённые у пользователя кадры (`.uagf`) этот же растеризатор прокручивает здесь в PNG — разбор визуальных
  ошибок без доступа к ПК.
- D3D12-часть проверяется на ПК пользователя по чек-листу каждого этапа.

## 8. Риски

| Риск | Что делаем |
|---|---|
| Калибровка и полпикселя DX7↔DX12 | эталонный растеризатор и тест калибровки; до первого показа `s = 1` |
| Чтение кадра назад тормозит | ленивое чтение через guard page; тесты поверхностей |
| ROExt перехватывает `DirectDrawCreateEx` | пролог горячего патча; проверка с ROExt |
| dgVoodoo не грузится из подпапки | проверка на этапе 2; запасной путь — замена файлов утилитой |
| Неизвестный путь реестра | этап 2: смотрим реальные значения на ПК пользователя |
| Всё графическое проверяется только у пользователя | маленькие этапы, подробный лог, сохранение кадров, чек-листы |
| Bink-заставка | растягивающий Blt на CPU в RT; проверка, если `openning.bik` есть |

## 9. Этапы v1

Каждый этап — сборка пользователю с чек-листом.

1. **Картинка как с dgVoodoo.** DX7-объекты, модель поверхностей, запись кадра, D3D12 при `s = r = 1`, окно и
   без рамки, VSync, ленивое чтение кадра, калибровка, лог, откат. Проверка: логин → выбор персонажа → игра,
   эффекты, скриншот, Alt+Tab, выход без MessageBox.
2. **Утилита.** Вкладки «Рендер», «Экран», «Кадры», «Диагностика»; переключение рендера; реестр; языки.
3. **Разрешение и масштаб интерфейса.** `s ≠ 1`, фильтр интерфейса, масштаб рендера, чтение кадра при масштабе.
4. **Сглаживание и фильтрация.** MSAA, alpha-to-coverage, анизотропия мира, мип-уровни; вкладка «Качество».
5. **HDR.** Вывод HDR10, маска интерфейса, вкладка «HDR».
6. **Чёткий текст.** Двойники картинок окон: перехваты vtable картинки окна и GDI (уточнение этапа 6).

План работ пишется по этапам: сначала отдельный план на этап 1, план следующего этапа — после проверки
предыдущего на ПК пользователя.

## 10. Вне v1

- **Часть 3** — 64-битный процесс-рендер (запись кадра через общую память), DLSS Frame Generation, Reflex,
  DLSS SR/DLAA. Векторы движения: камера из `CView+0x94` каждый кадр, объекты — через перехват `ProjectVertex`
  (`0x412cb0`) и `AddRP` (`0x412020`); jitter — сдвиг x/y экранных вершин.
- **Часть 4** — режим RTX Remix: выход в D3D9 с мировой геометрией из тех же перехватов, нормали по
  треугольникам, учёт запечённого освещения.
- HD-текстуры и HD-спрайты — не в этом проекте.
