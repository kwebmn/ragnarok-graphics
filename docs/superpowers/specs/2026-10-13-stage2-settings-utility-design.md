# uaRO Graphics — этап 2: утилита «uaRO Graphics Settings» (уточнение спецификации)

Основание:
- спецификация v1 `2026-10-13-uaro-graphics-design.md`: §1 (часть 2), §3.1, §5, §6, §7, §9 п. 2;
- что уже сделано: этапы 1B (`[display] mode`), 3 (`high_resolution`, `render_scale`, `ui_filter`), 0.4.0 (`sharpen`,
  Pause), 6 (`crisp_text`);
- разбор реестра клиента `docs/research/registry.md`;
- выгрузка реестра и `dinput.ini` с ПК пользователя (2026-10-13).

Документ заменяет §5 и §9 п. 2 спецификации v1 и уточняет §3.1, §6 и §7. Версии 0.6.0–0.6.3.

Решения пользователя:
- утилита меняет и разрешение игры;
- в утилите должно быть «максимум функций»;
- подход A — обычная программа Win32 без библиотек;
- разделы — списком слева;
- мелочи ревью 0.5.2 — отдельным кругом, после первой части утилиты.

## 1. Цель

- Одна программа, где игрок меняет всё, что влияет на картинку, звук и окно uaRO:
  - рендер и настройки uaRO Graphics;
  - режим экрана и разрешение игры;
  - настройки игры из реестра;
  - ROExt или uaRO Pad;
  - dgVoodoo.

  Без ручной правки ini и реестра, без прав администратора, с объяснением каждой настройки на EN, UA и RU.
- Работает и с dgVoodoo, и на Windows 7. Там нет нашего рендера, остальное работает.
- Полностью заменяет `setup.exe`.
- Пока игра запущена, резкость, масштаб рендера, фильтр интерфейса, чёткий текст, VSync и лимит FPS применяются в ней
  сразу.

Критерии успеха:
- Каждая настройка действует там, откуда её читает игра или драйвер. Проверяется по чек-листу на ПК пользователя.
- Перед первой записью сохраняется копия всего, что утилита может изменить. Вернуть её можно одной кнопкой.
- Утилита не записывает значений, с которыми игра не запустится: обязательные значения есть всегда, пределы
  проверяются.
- Ни одна запись не теряется из-за того, что игра запущена: то, что игра перезаписывает сама, при запущенной игре не
  меняется.

## 2. Где живут настройки

### 2.1 Реестр игры (`docs/research/registry.md`)

**Ключ.** `HKLM\SOFTWARE\WOW6432Node\Gravity Soft\Ragnarok` (32-битный вид, `Software\Gravity Soft\Ragnarok`).
`RoClient` — только для китайской службы.

**Две копии.** У `uaRO.exe` нет манифеста, поэтому Windows виртуализует его реестр:
- запись идёт в личную копию `HKCU\Software\Classes\VirtualStore\MACHINE\SOFTWARE\WOW6432Node\Gravity Soft\Ragnarok`;
- при чтении копии сливаются по значениям, и значение личной копии важнее общего (документация Microsoft «Registry
  Virtualization»).

У пользователя:
- экран, устройство D3D и звук есть только в общей копии (их записал `setup.exe` с правами администратора);
- всё, что сохраняет сама игра, лежит в личной копии;
- в общей копии есть старые копии части этих значений.

**Утилита виртуализацию не получает:** у неё есть манифест с `requestedExecutionLevel`. Поэтому слияние она делает сама
(§4).

**Что игра пишет сама** (`registry.md` §3):

| Когда | Что |
|---|---|
| нормальный выход | `UIRectInfo` (все окна), в главном ключе `SPRITEMODE`, `TEXTUREMODE`, `TRILINEARFILTER`, `FOG`, весь `Option` |
| каждая смена карты, выход к выбору персонажа | `ShortcutItem\<сервер>`, `SkillUseLevelInfo`, `NameBaloon\<сервер>\POS` |
| окно входа | `ID`, `CHECKSAVE`, `BITWISE` |
| список серверов, выбор персонажа | `NUMACCOUNT`, `NUMSERVER`, `CURSLOT` |
| окно подсказки дня, окно макросов Alt+M, книга, заставка | `SHOWTIPSATSTARTUP`, `ShortCutList`, `BookMark`, `BINKMODE` |

**Что игра не пишет никогда:** `WIDTH`, `HEIGHT`, `ISFULLSCREENMODE`, `BITPERPIXEL`, `DEVICECNT`, `MODECNT`,
`DEVICENAME`, `GUIDDEVICE`, `GUIDDRIVER`, `ISVOODOO`, `ISLIGHTMAP`, все значения звука.

Игра читает реестр только при запуске. Любое изменение действует со следующего запуска.

**Без чего игра не стартует:**
- ключ существует (иначе `setup.exe` запускается по кругу);
- `WIDTH` и `HEIGHT` не 0;
- `GUIDDEVICE` — настоящий IID устройства D3D (HAL);
- `BITPERPIXEL` равен 16 или 32 (для полного экрана).

Если `SOUNDMODE` нет, звука нет. Числа пишутся только как `REG_DWORD`: клиент не проверяет тип, и длинное значение
портит его буферы.

### 2.2 `uaro-graphics.ini`

Ключи v1 (§6 спецификации v1 с уточнениями этапов) и когда они действуют, если менять их при запущенной игре (§3.4):

| Ключ | Сразу | Со следующего запуска |
|---|---|---|
| `[renderer] backend` | | ✓ |
| `[display] mode`, `monitor`, `window_width`, `window_height` | | ✓ |
| `[display] high_resolution`, `ui_filter`, `crisp_text` | ✓ | |
| `[quality] render_scale`, `sharpen` | ✓ | |
| `[frames] vsync`, `fps_limit` | ✓ | |
| `[frames] allow_tearing` | | ✓ (флаг цепочки показа) |
| `[debug] log` | ✓ | |

Новый раздел `[utility] language = ` хранит язык утилиты: `en`, `uk`, `ru`, пусто — язык Windows. Драйвер разделы, которых
не знает, пропускает.

`install.bat` дописывает новые ключи в конец файла. Поэтому в файле бывают повторы разделов, например два `[quality]`.
Редактор ini (§3.2) правит каждую копию ключа. Новый ключ он добавляет в последний из одноимённых разделов.

### 2.3 ROExt и uaRO Pad

**ROExt.** Имя своего ini ROExt держит строкой в DLL: старая сборка читает `.\dinput8.ini`, новая (у игроков это
`dinput.dll`) — `.\dinput.ini`. Утилита узнаёт ROExt по содержимому DLL, а не по имени файла:
- в DLL есть строка `ROExt`;
- имя ini — найденная в DLL строка `.\<имя>.ini`.

Активны DLL, которые игра действительно загрузит: `dinput.dll` в папке клиента и `dinput8.dll` в папке клиента (его
подгружает системный `dinput.dll`). Копии `.bak` неактивны. Если активны и ROExt, и uaRO Pad, утилита показывает оба.

Ключи `[ROExt]`:
- `MouseFreedom`, `RemapMouseButtons` (кнопки мыши 3–5 → F24–F22), `RemapAltF4` (Alt+F4 → Alt+PrintScreen),
  `KeyRemap`;
- `AutoFreeCPU` (0, 1 или миллисекунды), `WindowOnTop`, `WindowLock` (без рамки и на месте; без своего размера — на
  весь экран без панели задач);
- `WindowPosX`, `WindowPosY`, `WindowWidth`, `WindowHeight` (0 — не задано), `CodePage` (−1 — не менять), `MinimizeKey`
  (только старая сборка).

Что делает `KeyRemap` и как работает `MouseFreedom` новой сборки, неизвестно. Для выпуска 0.6.3 нужен `dinput.dll`
ROExt от пользователя (§12).

**uaRO Pad** — `dinput.dll`, в котором есть строка `uaro-pad.ini`. Он заменяет ROExt: по инструкции ROExt
переименовывают в `.bak`. Утилите нужны ключи окна и мыши:
- `[mouse] freedom`, `lock`, `focus_click`, `middle`, `button4`, `button5`;
- `[window] borderless`, `position`, `background_sleep_ms`.

Остальное у uaRO Pad настраивается в его меню в игре.

### 2.4 dgVoodoo

`dgVoodoo.conf` — текстовый ini (CRLF). `install.bat` копирует его в `dgvoodoo\`. Утилита пишет обе копии одинаково:
какую из них читает dgVoodoo, загруженный из подпапки, не проверялось.

Ключи для игрока:
- `[General]`: `FullScreenMode`, `ScalingMode`, `KeepWindowAspectRatio`, `CaptureMouse`, `Brightness`, `Color`,
  `Contrast`;
- `[GeneralExt]`: `FreeMouse`;
- `[DirectX]`: `Filtering`, `Antialiasing`, `Resolution`, `ForceVerticalSync`, `dgVoodooWatermark`.

## 3. Устройство

### 3.1 Файлы

| Файл | Что |
|---|---|
| `uaro-graphics.exe` | утилита, рядом с `uaRO.exe`; в пакете — `uaro-graphics\uaro-graphics.exe`, `install.bat` копирует её на место |
| `uaro-graphics-backup\<ГГГГ-ММ-ДД-ЧЧММСС>\` | резервные копии (§4.6); `uninstall.bat` их не удаляет |
| `uaro-graphics-report.txt` | отчёт для форума (§7) |

Утилита 32-битная, как драйвер. Манифест:
- `asInvoker`;
- `PerMonitorV2` с запасом `System` для старых Windows;
- Common Controls 6;
- `supportedOS` от Windows 7 до 10.

`d3d12.dll`, `dxgi.dll` (для HDR — `IDXGIOutput6`) и `shcore.dll` (`GetDpiForMonitor`) загружаются при работе: утилита
запускается и на Windows 7. Импортирует она только системные DLL Windows 7 — это проверяет `tools/check_exe.py`.

### 3.2 Ядро: `src/core/settings/` (переносимое, тесты на Linux)

- **`schema`** — описание каждой настройки:
  - id, раздел утилиты, хранилище и место (раздел и ключ или подключ и имя);
  - тип (флаг, число в пределах, перечисление со значениями файла, строка до N символов) и значение по умолчанию;
  - когда действует: сразу или со следующего запуска;
  - кто ещё пишет: игра или только утилита;
  - выпуск, в котором появляется.
- **`ini_edit`** — правка ini без потери комментариев (`applyIniEdits` из uaRO Pad, с его тестами) и чтение, согласованное
  с `parseConfig`. Повторы разделов — как в §2.2.
- **`game_registry`** — две копии реестра в памяти (дерево ключей → значения с типом):
  - действующее значение;
  - план записи (§4.2);
  - набор для первого запуска (§4.3);
  - выгрузка и загрузка в файл `.reg` (§8).
- **`screen`** — мониторы, выбор игрока и что из него записать (§5); что сейчас у игры с учётом ROExt.
- **`input_module`** — по байтам DLL: ROExt (и имя его ini), uaRO Pad или неизвестный DLL.
- **`presets`**, **`report`** (текст отчёта без логина), **`log_digest`** (главное из `uaro-graphics.log`).
- **`compat_flags`** — разбор и правка строки флагов совместимости (`~ RUNASADMIN HIGHDPIAWARE …`).
- **`strings`** — все тексты на трёх языках. Тест проверяет, что у каждого текста есть все три перевода и в каждом одни
  и те же подстановки.
- **`live_config`** — для драйвера: какие ключи применить сразу, какие — со следующего запуска (§3.4).

### 3.3 Слой Windows: `src/app/`

- **Окно утилиты:** список разделов, страницы, ряды «подпись — элемент — пометки» (§6), DPI, клавиатура, подсказки.
- **Ввод-вывод:**
  - реестр: общая копия — 32-битный вид HKLM, только чтение; личная копия — HKCU, `KEY_WOW64_64KEY`, без
    перенаправлений;
  - файлы: ini пишется во временный файл, потом `MoveFileExW(REPLACE_EXISTING | WRITE_THROUGH)`.
- **Проверки:**
  - запущена ли игра: процессы `uaRO.exe` с путём в этой папке (`QueryFullProcessImageNameW`);
  - запущена ли утилита с правами администратора (`TokenElevation`);
  - система: Windows через `RtlGetVersion`, видеокарта и D3D12 — `probeD3D12` драйвера, мониторы (§7).
- **Действия:** запуск игры, `update.bat`, `uninstall.bat`, открытие лога и папки.
- **`app.rc`:** манифест, значок, версия и текст `dist/uaro-graphics.ini` (`RCDATA`) — по нему ini создаётся заново и
  сбрасывается к умолчаниям.

Сборка: цель `uaro-graphics` в `CMakeLists.txt` (только `WIN32`, статически `libgcc`/`libstdc++`, `-s`, `-municode`).
Спецификация v1 называла папку `tools/settings`. В `tools/` лежат скрипты, поэтому код утилиты будет в `src/app/`.

### 3.4 Драйвер: применение на лету

- `Context::present` раз в секунду сравнивает время записи и размер `uaro-graphics.ini`. Если они изменились, драйвер
  перечитывает файл через `parseConfig`, а `liveUpdate(running, fromFile)` из ядра возвращает новую рабочую
  конфигурацию и список ключей, которые ждут перезапуска.
- Как применяются ключи:
  - `render_scale` и `high_resolution` — через обычный `planScale` следующего кадра;
  - `sharpen`, `vsync`, `fps_limit` — через параметры показа;
  - `ui_filter` — через `setUiSharp`;
  - `crisp_text` — `crisp::install` или `crisp::uninstall`;
  - `log` — уровень лога.
- Строка в логе на каждое изменение: `settings: uaro-graphics.ini changed: sharpen 50 -> 80; at the next start: mode`.
- Если файл не прочитался (утилита как раз подменяет его), драйвер пробует на следующей проверке.

## 4. Правила записи

### 4.1 Когда можно писать

| Что | Когда утилита пишет | Когда действует |
|---|---|---|
| `uaro-graphics.ini` | всегда | по §2.2 |
| реестр: значения, которые игра не пишет (экран, звук, устройство, `ISLIGHTMAP`) | всегда | со следующего запуска |
| реестр: значения, которые пишет игра (§2.1) | только при закрытой игре | со следующего запуска |
| ini ROExt, `uaro-pad.ini`, `dgVoodoo.conf` | только при закрытой игре | со следующего запуска |

- Пока игра запущена, поля второго рода серые, на странице подсказка «закрой игру».
- Перед записью утилита ещё раз проверяет, не запустилась ли игра.
- Если клиентов несколько, они перезапишут друг друга, поэтому утилита проверяет все.

### 4.2 Реестр: две копии

- **Действующее значение** = личное, если оно есть, иначе общее, иначе значение игры по умолчанию (`registry.md`).
- **Запись** идёт в личную копию. Если новое значение равно общему, личное удаляется, и этим значением снова управляет
  `setup.exe`.
- **Расхождение копий.** Если личное значение отличается от общего, у поля пометка «setup.exe: …» и кнопка «как в
  setup.exe» (удалить личное). У звука пометка одна на всё устройство (режим, частота, разрядность, звуки, колонки):
  «В setup.exe: …» и кнопка «Как в setup.exe» (0.6.2).
- **Запуск игры от администратора.** Если у `uaRO.exe` стоит флажок `RUNASADMIN` (§7), игра личную копию не видит.
  Утилита предупреждает и предлагает снять флажок; флажок в HKCU снимается без прав администратора.
- **Утилита запущена от администратора.** Полоса предупреждения: игра, запущенная из такой утилиты, тоже получит права
  администратора и не увидит личную копию. Кнопки запуска игры неактивны.

### 4.3 Первый запуск без `setup.exe`

Если ключа игры нет ни в одной копии, утилита создаёт в личной копии всё, что нужно для старта:
- экран по §5 (по умолчанию — окно, самый большой стандартный размер, который помещается);
- `BITPERPIXEL = 32`;
- `GUIDDEVICE` = `IID_IDirect3DHALDevice`, `GUIDDRIVER` = нули, `DEVICENAME = Direct3D HAL`;
- `SOUNDMODE = 1`, `DIGITALRATETYPE = 0`, `DIGITALBITSTYPE = 0`, `NUMSAMPLETYPE = 0`, `SPEAKERTYPE = 0`,
  `PROVIDERNAME = No Provider`;
- `ISLIGHTMAP = 1`, `SPRITEMODE = 2`, `TEXTUREMODE = 2`, `TRILINEARFILTER = 0` (как у игры по умолчанию), `ISVOODOO = 0`.

Видит ли игра ключ, которого нет в общей копии, проверяется на чистой системе (§12).

### 4.4 ROExt рядом с экраном

Если ROExt активен и задаёт окну свой размер (`WindowWidth` и `WindowHeight` не 0) или стоит `WindowLock = 1`, то в
оконном режиме он сильнее реестра. Поэтому раздел «Экран» в оконном режиме пишет `WindowWidth` и `WindowHeight` = размер
игры. Остальные ключи ROExt он не трогает.

### 4.5 Ошибки записи

- Каждое значение реестра пишется отдельно.
- Если какое-то не записалось, утилита называет его и причину. Записанные остаются.
- Ini пишется целиком через временный файл: драйвер никогда не прочтёт половину.

### 4.6 Резервные копии

Перед первой записью за запуск утилиты она сохраняет в `uaro-graphics-backup\<дата-время>\`:
- обе копии ключа игры в `.reg` (общая — только для справки);
- `uaro-graphics.ini`, ini ROExt, `uaro-pad.ini`, `dgVoodoo.conf` (обе копии), какие есть.

«Восстановить»:
- возвращает файлы;
- заменяет личную копию ключа игры сохранённой;
- общую копию не трогает (утилита её не меняет).

Хранится 20 последних копий: более старые удаляются сами. «Оставить 5 последних» удаляет остальные.

## 5. Экран

### 5.1 Что делает клиент (`registry.md` §2)

**Размер игры.** `WIDTH`×`HEIGHT` клиент берёт как есть: нет ни списка режимов, ни минимума, ни максимума (интерфейсу
нужно не меньше 640×480).

**Окно** (`ISFULLSCREENMODE = 0`):
- клиентская область `WIDTH`×`HEIGHT` по центру основного монитора, с заголовком, без рамки изменения размера;
- игра рисует в фактическую клиентскую область, `BITPERPIXEL` не используется.

Окно больше рабочего стола Windows урежет при создании, и игра получит меньший размер.

**Полный экран** (`ISFULLSCREENMODE = 1`):
- окно `WS_POPUP`, развёрнутое, исключительный режим, `SetDisplayMode(WIDTH, HEIGHT, BITPERPIXEL)`;
- при потере фокуса клиент сворачивается, при возврате разворачивается.

Наш драйвер режим монитора не меняет и показывает игру окном без рамки на весь монитор (§4.1 v1). Поэтому Alt+Tab
мгновенный, но игра при нём сворачивается — как и с dgVoodoo.

### 5.2 Что выбирает игрок

| Выбор | Значения |
|---|---|
| Показ | «Во весь экран» / «В окне» |
| Монитор | список: номер, разрешение, масштаб Windows, «основной»; номера как у драйвера — 0 основной, дальше в порядке `EnumDisplayMonitors` (`monitorIndex` из ядра) |
| Размер интерфейса `u` | 100, 125, 150, 175, 200, 250, 300 % или свой (100–400 %): сколько точек экрана на точку игры |
| Размер окна `W` (в окне) | стандартные размеры игры 1920×1080, 1600×900, 1366×768, 1280×720, 1024×768, умноженные на `d`, и самый большой размер с пропорциями монитора — те, что помещаются в `A` вместе с заголовком; или свой |

Обозначения:
- `P` — разрешение монитора;
- `A` — его рабочая область (без панели задач), в настоящих точках;
- `d` — масштаб Windows этого монитора, в процентах (175 %);
- `L` — размер игры (`WIDTH`×`HEIGHT`).

`s` — во сколько раз игра увеличена на экране: `P / L` во весь экран, `W / L` в окне. Подсказка под выбором: «игра
2194×1234 → экран 3840×2160, интерфейс ×1,75». У целого `s` (×2, ×3) пометка «самый чёткий интерфейс».

### 5.3 Что записывается

| | uaRO Graphics | dgVoodoo |
|---|---|---|
| Во весь экран | `ISFULLSCREENMODE = 1`, `L = round(P · 100 / u)`; ini `mode = auto`, `monitor` | `ISFULLSCREENMODE = 1`, `L` — только из настоящих режимов монитора (32 бит): dgVoodoo может переключать режим; `u` показывается как `P · 100 / L`; монитор — тот, что выбран в dgVoodoo (до 0.6.3 — основной) |
| В окне | `ISFULLSCREENMODE = 0`, `L = round(W · 100 / u)`; если `u = d` и монитор основной — ini `mode = auto`, `window_width = window_height = 0`, иначе `mode = window`, `window_width`×`window_height = round(W · 100 / d)`, `monitor` | `ISFULLSCREENMODE = 0`, `u = d` (выбор недоступен, подсказка «с dgVoodoo размер интерфейса задаёт масштаб Windows»), `L = round(W · 100 / d)` |

- `BITPERPIXEL = 32` всегда.
- Если ROExt задаёт окну размер, туда пишется тот же размер (§4.4).
- **Ограничение окна:** игра создаёт окно на основном мониторе в логических точках (настоящие точки / масштаб
  Windows). Окно `L` вместе с заголовком и рамкой должно поместиться в рабочую область основного монитора, иначе Windows
  его урежет. Такие сочетания недоступны, у них подсказка «не поместится».
- **Окна игры** после смены разрешения игра проверяет сама: окно, которое не помещается, при открытии встаёт на своё
  место по умолчанию, чат — в левый нижний угол.
- **«Сейчас»** — что получит игра из нынешних хранилищ:
  - реестр по §4.2;
  - размер ROExt, если он его задаёт, а при `WindowLock` без размера — «на весь экран без панели задач»;
  - наш ini.

  Пример у пользователя: «в окне · окно 3360×1890 · интерфейс 175 % · игра 1920×1080».

### 5.4 Полный экран на деле

Проверен на ПК пользователя в 0.6.1 (4K, 175 %): окно без рамки на весь монитор, панель задач скрыта, мышь попадает,
Alt+Tab работает. Окно выходило на точку меньше монитора (3839×2159): игра не знает о масштабе Windows и ставит его в
своих точках (2194×1234). С 0.6.2 драйвер ставит окно без рамки в настоящих точках монитора (поток на это время
per-monitor aware) и проверяет, где оно оказалось; если Windows поставила его иначе — как раньше, в точках игры.

Запасной путь, если полный экран перестанет работать: `ISFULLSCREENMODE = 0` и ini `mode = borderless` — окно игры
без рамки на весь монитор. Ограничение: `u ≥ d`, иначе окно игры при создании не поместится (§5.3).

## 6. Окно утилиты

**Расположение.**
- Слева список разделов: Рендер, Экран, Качество, Кадры, Звук, Игра, Чат и вход, Ввод и окно, dgVoodoo, Диагностика,
  Сервис.
- Справа страница выбранного раздела.
- Вверху справа язык: EN / UA / RU. По умолчанию — язык Windows, если он украинский или русский, иначе английский.
  Выбор хранится в `[utility] language`.

**Ряд настройки:**
- подпись и элемент: флажок, список, ползунок с числом, поле;
- подсказка при наведении — текст из комментария ini или своё пояснение;
- пометки:
  - «↻ после перезапуска игры»;
  - источник значения («setup.exe: 1920×1080», «ROExt»);
  - «закрой игру», если запись сейчас невозможна (§4.1).

**Внизу:**
- строка состояния: игра запущена или нет, сколько изменений не сохранено;
- кнопки «Применить», «Применить и запустить игру», «Отменить», «Закрыть». «Закрыть» спрашивает, если есть
  несохранённое.

**Пока игра запущена,** ползунки резкости и масштаба рендера записываются, как только их отпускают: так их удобно
сравнивать. «Отменить» возвращает значения, которые были при открытии утилиты.

**Окно** чёткое на любом масштабе: `WM_DPICHANGED` пересчитывает шрифт и размеры. Шрифт — системный шрифт сообщений.
Всё доступно с клавиатуры (Tab, стрелки, Alt+буква).

## 7. Диагностика

Строки зелёные, жёлтые или красные. У каждой есть пояснение, а где можно — кнопка «Исправить».

**Система:**
- Windows (версия, сборка);
- видеокарта, версия драйвера, видеопамять (32-битной программе Windows сообщает не больше 3072 МБ: тогда «не меньше
  3072 МБ», 0.6.2);
- создаётся ли устройство D3D12 уровня 11_0.

**Мониторы** (у каждого):
- разрешение и частота (`EnumDisplaySettings`);
- масштаб Windows (`GetDpiForMonitor`);
- рабочая область;
- HDR (`IDXGIOutput6`).

**Установка:**
- какой `ddraw.dll` стоит: наш (с версией из `uaro-graphics\version.txt`), dgVoodoo или никакого;
- есть ли `dgvoodoo\`;
- модуль ввода (§2.3);
- можно ли писать в папку клиента. Клиент в Program Files — жёлтая строка: Windows подменяет файлы игры.

**Флажки совместимости у `uaRO.exe`** (`AppCompatFlags\Layers` в HKCU и в 64-битном виде HKLM):
- `RUNASADMIN`, режимы `WINXPSP2`/`WINXPSP3`/`WIN7RTM`/…, `HIGHDPIAWARE`, `DPIUNAWARE`, `GDIDPISCALING`,
  `DISABLEDXMAXIMIZEDWINDOWEDMODE`, `16BITCOLOR`, `640X480`;
- у каждого сказано, что он ломает;
- «Снять» — для флажков в HKCU. Флажки в HKLM меняются только из свойств файла, с правами администратора.

**Реестр:**
- есть ли общая и личная копии;
- где копии расходятся по экрану и звуку.

**Лог:**
- главное из `uaro-graphics.log`: какой рендер и почему, ошибки, последние fps, строки чёткого текста;
- «Открыть лог», «Открыть папку».

**«Отчёт для форума»:**
- система, мониторы, версии, рендер, настройки, действующий экран, флажки, модуль ввода, выдержка из лога (до 40 строк);
- копируется в буфер обмена и пишется в `uaro-graphics-report.txt`;
- без логина (`ID`), имён персонажей и серверов.

## 9. Пакет и установка

- В пакете есть `uaro-graphics\uaro-graphics.exe`.
- **`install.bat`** копирует утилиту рядом с `uaRO.exe` и в конце пишет, что настройки — в `uaro-graphics.exe`.
- **`update.bat`:**
  - перед копированием ждёт до 10 секунд, пока закроется `uaro-graphics.exe`, иначе просит его закрыть;
  - пока игра запущена, обновление по-прежнему отказывается работать.
- **`uninstall.bat`** удаляет утилиту. `uaro-graphics-backup\` оставляет и говорит об этом.
- **`tools/package.sh`** кладёт утилиту в пакет. С 0.6.3 он пишет ещё и `release/version.txt` (та же строка, что
  `uaro-graphics\version.txt`).
- **`tools/check_package.py`** проверяет утилиту в пакете, **`tools/check_exe.py`** — её импорты.

## 10. Проверка

**Linux (ядро):**
- схема: у каждой настройки есть хранилище, пределы, значение по умолчанию и тексты на трёх языках;
- правка ini:
  - комментарии и CRLF сохраняются;
  - повторы разделов обрабатываются;
  - новый ключ попадает в нужный раздел;
  - файл после `install.bat` остаётся читаемым;
- две копии реестра:
  - чтение;
  - запись в личную копию;
  - «равно общему → удалить личное»;
  - первый запуск;
  - `.reg` туда и обратно;
  - только `REG_DWORD` для чисел;
- экран: таблица §5.3 для обоих рендеров, ограничение окна, пример пользователя, ROExt с размером и с `WindowLock`;
- модуль ввода по байтам DLL: старый ROExt (`.\dinput8.ini`), новый, uaRO Pad, неизвестный;
- флажки совместимости: разбор, снятие, пустая строка;
- `live_config`: что сразу, что после перезапуска, неизменённый файл;
- отчёт без логина;
- выдержка из лога;
- пресеты.

**Windows:** сборка без предупреждений, `check_exe.py`, `check_dll.py`, чек-лист `TEST.ru.md` каждого выпуска на ПК
пользователя.

Чек-лист 0.6.0, по порядку:
1. Полный экран с нашим рендером (§5.4).
2. Окно с размером интерфейса, не равным масштабу Windows.
3. Резкость и масштаб рендера меняются в запущенной игре.
4. Диагностика верно показывает монитор (3840×2160, 175 %).
5. Резервная копия и восстановление.
6. Предупреждение о запуске утилиты от администратора.

## 13. Вне этапа

- Вкладки HDR и сглаживания (MSAA, анизотропия) появятся вместе с этапами 4–5.
- Настройки внутри игры поверх кадра.
